# ZokoGames SDK for Unity (WebGL)

UPM package `com.zokogames.sdk` (Unity 2021.3 or newer). A static facade, `ZokoSDK`, over the browser SDK
`window.ZokoGames.SDK` (`https://sdk.zokogames.com/zokogames-sdk-v1.js`) through a `.jslib` bridge. In the Editor and in every
non-WebGL player a built-in simulator answers instead, so the game runs unchanged without a browser.

Version 1.8.3 (written against the JavaScript SDK `@zoko/sdk` 1.8.1). Changes: [CHANGELOG.md](./CHANGELOG.md).
Status: run in Unity 6 (6000.3.28f1). Embedded in a full URP game, the package imported and compiled with no warnings, and a
release WebGL build (Brotli, IL2CPP high stripping) ran in Chrome against the production SDK: in the portal frame as a guest and
in local mode, with init, loading progress, gameplay start and stop, settings and the mute switch, cloud save and restore,
game context, the user and ad-block calls, and no console errors. Unity 2021.3 to 2023 are compiled with a real C# compiler
against stubs of the Unity API only. If something fails on import, send the engine version and the exact error to developer
support.

`Application.runInBackground`: browsers throttle a hidden tab. Set `Application.runInBackground = true` (the sample scripts do) so timers, audio and network keep running while an ad overlay or another tab has focus; WebGL builds otherwise stop updating when the tab loses focus. Ads mute `AudioListener` automatically (`ZokoSDK.Ad.MuteAudioDuringAds`, default on) and restore it afterwards, and the portal's mute setting is applied to `AudioListener.pause` after init and on every change (`ZokoSDK.Ad.FollowPortalMute`, default on; set it false before `Init` to handle `Game.SettingsChanged` yourself). After an ad, a sign-in prompt or a checkout the bridge gives keyboard focus back to the canvas.

## Install

Three routes; use one of them in a project, never two (they would define the same classes twice):

- **`.unitypackage`** (simplest): download `zokogames-unity-<version>.unitypackage` from the console's Plugins page and open it, or
  **Assets > Import Package > Custom Package**. It imports the plugin into `Assets/ZokoGames/` (samples in `Assets/ZokoGames/Samples/`)
  and the WebGL template into `Assets/WebGLTemplates/ZokoGames/`; then select the template with **ZokoGames > Install WebGL Template**
  (or in Player Settings) and skip steps 1, 2 and 4 below.
- **OpenUPM**: `openupm add com.zokogames.sdk`, then steps 2 to 4.
- **Package Manager from disk or git**, step 1 below, then steps 2 to 4.

1. Package Manager > Add package from disk > `unity/package.json` from the download, or copy the folder into your project's
   `Packages/` folder (an embedded package). From 1.6.1 every file and folder ships with its `.meta` file (stable GUIDs,
   generated by `tools/unity-meta.mjs`), so the package should also import read-only, from your own git repository or a tarball
   (Unity writes no `.meta` files for those). That route has not been tried in an editor yet.
   The package depends on `com.unity.ugui` (the `ZokoBanner` component), which every Unity template project already has.
2. Menu **ZokoGames > Install WebGL Template** copies the template to `Assets/WebGLTemplates/ZokoGames` and selects it. It
   loads the SDK script and reports the engine download to the portal's loading bar. With your own template, add
   `<script src="https://sdk.zokogames.com/zokogames-sdk-v1.js"></script>` to `<head>` before the Unity loader (the bundled template already includes it; add it only for a custom template) and keep the canvas
   id `unity-canvas`.
3. Optional: **ZokoGames > Create Simulator Settings** creates `Assets/Resources/ZokoSDKSettings.asset`.
4. Import the **Demo** sample from the Package Manager: one MonoBehaviour that touches every module (keys A, R, G, H, U, F, T, S, B) and `ZokoStoreExample`, a minimal purchase flow (catalogue, buy, consume, inventory, error codes).

How it works: `Plugins/WebGL/ZokoSDK.jslib` calls the JS SDK and answers a hidden `ZokoSDKBridge` GameObject through
`SendMessage`, tagging each call with a request id. Synchronous calls (cloud save, invite parameters, sandbox flag) use direct return values.

## Quick start

```csharp
using System.Collections.Generic;
using UnityEngine;
using ZokoGames;

public class Boot : MonoBehaviour
{
    async void Start()
    {
        Application.runInBackground = true;              // WebGL: keep running while an ad overlay has focus
        await ZokoSDK.InitAsync();                       // or ZokoSDK.Init(err => ...)
        Debug.Log(ZokoSDK.Environment + (ZokoSDK.IsSimulated ? " (simulated)" : ""));

        ZokoSDK.Game.SettingsChanged += s => AudioListener.pause = s.MuteAudio;
        ZokoSDK.Game.LoadingStop();
        ZokoSDK.Game.GameplayStart();

        // Ad: audio is muted for you (ZokoSDK.Ad.MuteAudioDuringAds); pause gameplay in adStarted, resume in adFinished / adError
        ZokoSDK.Ad.RequestAd(ZokoAdType.Rewarded,
            adStarted: () => Time.timeScale = 0,
            adFinished: () => { Time.timeScale = 1; GiveReward(); },
            adError: e => Time.timeScale = 1);

        // Cloud save (PlayerPrefs style, synchronous)
        ZokoSDK.Data.SetInt("level", ZokoSDK.Data.GetInt("level", 0) + 1);

        // Store (see Samples~/Demo/ZokoStoreExample.cs for the full flow)
        if (ZokoSDK.Store.IsAvailable)
        {
            try
            {
                var items = await ZokoSDK.Store.GetCatalogItemsAsync();
                string bought = await ZokoSDK.Store.BuyItemAsync(items[0].Sku);   // verify on your server
            }
            catch (ZokoException e) when (e.Error.Is(ZokoErrorCodes.Store.PurchaseCancelled)) { }
            string purchaseToken = await ZokoSDK.Store.GetPurchaseTokenAsync();   // signed ownership token for your backend
        }
    }
    void GiveReward() { }
}
```

`ZokoBanner` (Add Component > ZokoGames > Zoko Banner) puts a banner over a UI `RectTransform`: set `containerId` and `size`
(responsive or a static size); it requests on enable and clears on disable.

### Leaderboard score encryption

Seal a score with your board key and submit it (SDK 1.8.0, no hand-written AES needed):

```csharp
string payload = await ZokoSDK.User.EncryptScoreAsync(score, KEY);
await ZokoSDK.User.SubmitScoreAsync(payload, score);
```

For a score earned offline pass `earnedAt` (Unix ms) as the third argument. Guests get `userNotAuthenticated`. On a portal older than SDK 1.8.0 the call fails with `other`; seal the score yourself with the board's documented scheme there.

### Cloud save for PlayerPrefs (IndexedDB mirror)

WebGL keeps `PlayerPrefs` and `Application.persistentDataPath` files in the browser's IndexedDB (`/idbfs`). To save them to the player's cloud save, set the WebGL template variable `ZOKO_MIRROR_INDEXEDDB` to `true` in Player Settings > Resolution and Presentation (template `ZokoGames`), or set `window.ZOKO_MIRROR_INDEXEDDB = true` in the page before the loader runs. The template restores the cloud copy before Unity starts, so the game reads the restored files on its first frame.

- `PlayerPrefs.Save()` writes are picked up within a few seconds and uploaded in the background.
- The mirrored data may not exceed 1 MiB in total.
- The data module must be enabled for the game in the developer console, otherwise the mirror does nothing.
- `ZokoSDK.Data.StopMirrorIndexedDB()` stops mirroring.

## Room data channel

`ZokoSDK.Game.Room` (SDK 1.3.0) lets the players of one room exchange small messages and share a tiny host-written state without your
own server. It is for game data, not text chat. The channel exists after `Game.UpdateRoom(...)` (or after joining from an invite) and ends
with `Game.LeftRoom()`; it needs a signed-in player and a portal with realtime enabled, otherwise calls fail with `roomUnavailable`.
Limits: 8 KB per message or patch, 20 messages per second, 64 KB of state, state keys of 1 to 40 characters of `A-Z a-z 0-9 _ . : -`.
Events are raised on the Unity main thread (the bridge delivers them through `SendMessage`). Payloads are JSON: pass a Dictionary or
List, a JSON string (`SendJson`) or a `[Serializable]` class (`SendTyped<T>` and `message.As<T>()` use `JsonUtility`).

In the Editor and non-WebGL players the simulator provides one room with one member (`sim-player`, the host) and **loops your own
messages and state changes back** to the handlers, so a single instance can exercise the whole flow. A real portal never echoes your own messages.

```csharp
[System.Serializable] class Move { public int cell; public string mark; }

async void StartMatch()
{
    await ZokoSDK.InitAsync();
    ZokoSDK.Game.Room.MessageReceived += m =>
    {
        var mv = m.As<Move>();                                      // from the other player
        Board.Place(mv.cell, mv.mark);
    };
    ZokoSDK.Game.Room.StateChanged += (state, change) => Debug.Log("turn " + ZokoSDK.Game.Room.GetState("turn"));
    ZokoSDK.Game.Room.HostChanged += (hostId, isHost) => { if (isHost) ZokoSDK.Game.Room.SetState("turn", "X"); };
    ZokoSDK.Game.Room.Error += e => Debug.LogWarning("room: " + e);

    await ZokoSDK.Game.UpdateRoomAsync(new ZokoRoomUpdate { RoomId = "match-1", IsJoinable = true });   // the first player is the host
}

void OnCellClicked(int cell)
{
    ZokoSDK.Game.Room.SendTyped(new Move { cell = cell, mark = "X" });
    if (ZokoSDK.Game.Room.IsHost) ZokoSDK.Game.Room.SetState("turn", "O");   // only the host writes state
}
```

## Error codes

Every failure carries a code and a message (`ZokoError.Code`, `ZokoError.Message`, `ZokoError.ContainerId`). Banner errors also carry the container id.
Compare against the constants instead of string literals: `if (err.Is(ZokoErrorCodes.Store.PurchaseCancelled)) ...`; `ZokoErrorCodes.Store.All` lists every code of a module.

| Code | Meaning |
|---|---|
| `adCooldown` | An ad was requested too soon after the previous one. |
| `adblock` | An ad blocker prevented the ad. |
| `adsDisabled` | Ads are switched off for this game or session. |
| `bannerCooldown` | The same banner container was refreshed within 30 seconds. |
| `bannersDisabled` | Banners are switched off for this game or session. |
| `catalogFetchFailed` | The store catalogue could not be loaded. |
| `consumeItemFailed` | The provider rejected the consume request. |
| `dataLimitExceeded` | Cloud save would exceed 1 MiB. |
| `dataModuleDisabled` | Cloud save is not enabled for this game. |
| `insufficientItemQuantity` | consumeItem asked for more than the player owns. |
| `inventoryFetchFailed` | The player inventory could not be loaded. |
| `invalidArgument` | An argument failed validation. |
| `invalidSize` | The banner size is not one of the supported sizes. |
| `itemNotConsumable` | consumeItem was used on a non-consumable item. |
| `itemNotInInventory` | consumeItem named an item the player does not own. |
| `maxRefreshReached` | The per-session banner refresh limit was reached. |
| `missingId` | A banner container id was empty. |
| `noAvailableSizes` | No responsive banner size fits the container. |
| `notCreated` | The banner container does not exist. |

## Local testing and mock mode

`ZokoSDK.IsSimulated` is true in the Editor and in any non-WebGL player. Ads show for `adDurationSeconds`, cloud save persists in
PlayerPrefs (`zoko-sdk-sim-data`; **ZokoGames > Clear Simulated Cloud Save**), the store has a three-item catalogue and an inventory that
survives play sessions, and friends, login state, ad behaviour (fill, no fill, error), ad blocker and the disabled embed are all
tunable in `ZokoSDKSettings`. The room data channel is simulated with one member that receives its own messages and state changes. Calls always answer asynchronously, like the browser.

Serve the export from `localhost` first: the SDK then runs in its in-page local mode (fake ads, a fake player, a
`localStorage` cloud save), so every call works without the portal. To see the real requirements checklist and event log,
open `/preview` on the portal and enter your local address while you play.

## Build and export settings

- Player Settings > Publishing Settings > **Compression Format: Brotli** (or Gzip). Files then end in `.br` / `.gz` and the portal
  serves them with `Content-Encoding`. Keep **Decompression Fallback off**. "Disabled" also works but the initial download is larger.
- Resolution and Presentation > WebGL Template: **ZokoGames**.
- Other Settings: Managed Stripping Level High, IL2CPP code generation "Faster (smaller) builds", Strip Engine Code on; Texture compression
  ASTC (mobile) or DXT; avoid including unused packages and large StreamingAssets.
- Keep the initial download under 50 MB (20 MB for mobile): load big content through Addressables after the first scene instead of in
  the first build step.
- Do not use `Task.Wait()` / `.Result` on WebGL (single thread: deadlock). `await` and the callback forms are fine.

Portal limits for an uploaded build: 1,500 files, 250 MB unpacked, about 50 MB initial download (20 MB for mobile),
`index.html` at the archive root, every path relative. Files ending in `.br` or `.gz` are served with the matching
`Content-Encoding`, so an engine that requests exactly those file names (Unity) can ship pre-compressed files; an engine
that requests plain names (Godot, Cocos, Phaser, GameMaker, Defold, Construct) must ship them uncompressed.

Loading: call the loading calls so the portal can show a progress bar: the WebGL template already reports `loadingStart` / `loadingProgress` / `loadingStop` for the engine download. For your own
first scene, call `ZokoSDK.Game.LoadingStart()` then `LoadingProgress(p)` and `LoadingStop()` when the player can act.

## Troubleshooting

- `sdkNotLoaded` or "ZokoGames is undefined": the page has no SDK script tag. Use the ZokoGames WebGL template or add the tag.
- `.jslib` ignored: it must stay in `Plugins/WebGL/` and the build target must be WebGL.
- Every call fails with `sdkNotInitialized`: wait for `Init` to finish before other calls.
- Brotli build will not load locally over plain http: use `localhost`, HTTPS, or Gzip.
- Banner stays empty in the Editor: the simulator only logs banner requests; test in a web build.
- `Task` never completes: you awaited on a thread other than the main thread.

## Upload

Build for WebGL with the ZokoGames template, zip the build folder contents so `index.html` is at the archive root, and upload the zip in
the developer console. Documentation: `/docs/engines/unity` on the portal.
